# Páginas: detalhes por página

Referência detalhada de cada página (dados, coleções, fórmulas, decisões de UX). O CLAUDE.md aponta para cá; ao mudar o comportamento de uma página, atualize a seção dela aqui.

## `irrigacao.html`

also hosts a **🌧️ Pluviometria** modal — rainfall log per **fazenda** with support for multiple **pluviômetros** and a yearly history/monthly bar-grid; collection `pluviometria` `{fazenda,pluviometro,data,mm}`, gated by `podeRegistrar()`/`podeGerenciar()`) (irrigation management — Leaflet map reusing registered talhão polygons as background context; admins draw individualized clickable **setor** polygons, the irrigador clicks a setor and logs a watering shift as a **two-step turno** (start it "now" → later finalize with the end time, one single record; a `horaFim`-empty record = turno em andamento) or via a manual complete entry; date defaults to today; setores are colored by recency-since-last-watering (heatmap: today→blue, 1-4d→green, 5-7d→yellow, 8-9d→orange, 10+→red, never→grey). Each setor belongs to a **talhão** (required at creation; fazenda is derived from the talhão), and the sidebar is a **Fazenda → Talhão (accordion) → Setores** hierarchy so the field worker finds the talhão first, then picks the setor inside it; talhão rows sort most-overdue first and opening one zooms the map to it. Per-setor history + full-history modal. Each setor carries an **area in hectares** (`areaHa`; `areaDoSetor(s)` falls back to computing from the polygon geometry via a spherical-area helper when `areaHa` is unset). Areas are edited **in `adubacoes.html`'s “📐 Setores” config modal** (per-talhão list of name + area fields, pre-filled with the geometry-computed value; writes `areaHa` back to `irrigacaoSetores`, and can also add area-only setores with empty `coordenadas`) — not in the irrigação setor modal. Admins can bulk-**import setores from Google Earth KML/KMZ** (JSZip via CDN unzips KMZ; DOMParser reads Placemark polygons — KML is lng,lat), each imported polygon mapped to a talhão (auto-suggested by centroid point-in-polygon). Collections: `irrigacaoSetores` (`{nome,fazenda,talhaoId,talhaoNome,coordenadas,areaHa,...}`), `irrigacaoRegistros`. Also hosts a **💧 Vazão** modal (`abrirVazao`) — live view of the ultrasonic **flow meters** (TUF-2000M) read by one ESP32 per meter (`vazao/medidor_vazao/`, Modbus RTU over RS485 → Firestore REST with a dedicated device account; see `vazao/README.md`): cards per meter (m³/h, online/offline by `ultimo.ts` age > 3 min, `ok:false` = RS485 not answering, Q < 60 = weak signal), a **referência (bomba) × comparado (lavoura)** comparison (difference %, ok/atenção/alerta vs `limitePct`, default 5 %) both live and for the day's volume, a ‹ dia › SVG chart of both series and per-meter volume (totalizer difference, fallback ∑vazão/60). Its listeners exist **only while the modal is open** (the ESP32 writes every minute). Admins (`podeGerenciar`) rename meters, set per-meter **alert limits** (`alertaMin`/`alertaMax` m³/h, `alertaMinutos` persistence, `alertaLigaDesliga`) and pick the pair/limit/`alertaDif`. **Alerts are evaluated by the ESP32 itself** (firmware ≥1.1, re-reads limits every 5 min): vazão baixa (only while flowing > 0,5 m³/h — a stopped pump is not an alert), vazão alta, medidor sem resposta 10 min, bomba ligou/desligou, and — on the referência ESP32 only, by GETting the comparado's `ultimo` each minute — diferença > `limitePct`; each episode notifies once on entry and once on recovery, writes a `vazaoAlertas` doc and optionally sends Telegram (`TELEGRAM_TOKEN`/`TELEGRAM_CHAT` live only in the ESP32's `config.h`, never in Firestore). The modal lists the last alerts (`query(vazaoAlertas, orderBy ts desc, limit 20)`, only while open) and flags cards out of the faixa. The **day chart** and the **📊 relatório** use Chart.js 4.4.0 + `chartjs-plugin-zoom` 2.0.1 (+ hammerjs, loaded in the head; wheel/pinch zoom and pan on x, `↺` reset; falls back to the SVG chart if Chart.js didn't load). The day chart's skeleton/instance is only rebuilt when the day or the meter list changes — on each minute's snapshot its datasets are swapped in place (`update('none')`) so the viewer's zoom survives. The relatório (`<details>`, loaded on open; grupos dia·30 dias / semana·12 semanas (Monday-based) / mês·12 meses; métrica volume m³ or horas de bomba = minutes with flow ≥ `VZ_MIN`) reads per-day summaries from **`vazaoMedidores/{id}/resumos/{dia}`** (`{dia,volume,exato,minutosFluxo,vazaoMax,vazaoMedia,pontos}`), which the **app computes from `dias/{dia}` on first view and caches** (`vzResumoDia`, same calc as the day table); yesterday and today are always recomputed and never cached (the ESP32 can still deliver queued minutes), and days with no `dias` doc after the meter's first day are cached as `pontos:0`. Collections: `vazaoMedidores/{id}` (`ultimo` written by the ESP32 via PATCH+updateMask; `nome`/`alerta*` by the app) + subcollection `dias/{YYYY-MM-DD}` (`pontos` map `hHHMM` → CSV `"vazao,total,q"`, `campos`), `vazaoConfig/geral` (`{ref,comp,limitePct,alertaDif}`), `vazaoAlertas` (`{medidor,tipo,nivel,texto,dia,hora,ts}`, written by the ESP32). **`adubacoes.html` reads `irrigacaoSetores`**: when an aplicação's `modo==='Fertirrigação'`, each product shows a **kg-per-setor** breakdown (dose kg/ha × each setor's area), reusing the same `areaHectares`/`areaDoSetor` helpers

## `herbicida.html`

weed control / herbicide application — Leaflet map reusing registered talhão polygons, colored by status: não iniciado→grey / aplicando→orange / concluído→green (status derived from history, no stored status field). Two methods: **costal** (manual, counted in *bombas* per person) and **trator** (mechanized, counted in *tanques*). The talhão panel is a **live "turma de hoje" board** for the encarregado to manage the crew *during* the day: each worker is a big **[− N +] counter** he taps as bombas are applied. Taps mutate an optimistic local cache (`diaCache`) and update the DOM synchronously, then a 350ms-debounced save writes the whole day's `pessoas` array to that talhão+day's `herbicidaRegistros` doc (created lazily on first change) — the local cache is what makes rapid taps accumulate correctly instead of racing on the snapshot value. A single `herbicidaRegistros` doc per talhão+day is the day's session (add/remove crew, toggle costal/trator); a new day with no session yet **pre-seeds the turma from the last day of the ciclo** (same people, counters at 0) so the encarregado just keeps tapping. A "＋ lançar em outra data" link opens the old modal for manual/retroactive entries. The **fecharTalhão** action records the talhão's area on a date (`herbicidaConclusoes`) — this solves "they can't estimate partial hectares day-to-day": hectares only count when the talhão is finished. A talhão's *ciclo atual* = registros after the last conclusão (so herbicida repeats per safra). Report modal filters by período+fazenda → hectares aplicados (from conclusões), bombas/tanques per person (uses worker **full name**; the field UI uses **apelido**), where each worked, a **per-day breakdown**, and an optional agrado calc (`configHerbicida/geral`: valorPorBomba/valorPorTanque/valorPorHa). The report is **exportable to PDF** (`exportarRelatorio` builds an inline-styled `#area-impressao-herb` and calls `window.print` under `body.imprimindo` — same print pattern as `adubacoes.html`). Workers come from `equipeEmpregados` (now has an `apelido` field added in `equipe.html`). Collections: `herbicidaRegistros`, `herbicidaConclusoes`, `configHerbicida`

## `cotacoes.html`

supplier price quotes — cloned from `pedidos.html`'s map/area-selection; the Planejamento tab plans what's needed, the Cotação tab collects per-supplier prices — including per-supplier alternative products — and compares, the Comparar tab derives products+prices from the cotações and lets an agronomist register each product's guarantees/composition to rank cost per kg of active ingredient. Collections: `cotacoes`, `garantiasProdutos`

## `calibracao.html`

**sprayer calibration** — tabbed tool, one tab per calibration *tipo* in the `TIPOS` config array (`barra`/herbicida, `turbina`/foliar, `drench`/turbina-adaptada), designed so new types are added by extending `TIPOS` + a calc branch. Each tab is a live-computing form: `barra`/`turbina` share `calcAspersao` — velocidade from distância+tempos (3.6·d/t), vazão total dos bicos (variable count), **volume L/ha = vazãoTotal·600/(velocidade·largura)**, ha/tanque, autonomia; `drench` uses `calcDrench` — **L/metro linear = vazão ÷ velocidade(m/min)**, L/planta, m/tanque. Saved records go to collection `calibracoes` (`{tipo,nome,fazenda,data,dados,resultado,obs,...}`), listed per-tab, admin-deletable. Formulas validated against the owner's handwritten example (113 m / 91 s / 3 bicos → 247 L/ha, 8,1 ha/tanque, 9,5 h). Gated by `nivelAcesso('calibracao')`

## `avaliacoes.html`

**field/experiment evaluation** — Leaflet map reusing registered talhão polygons as context; the field worker marks a plant with **🎯 Marcar aqui (GPS)** (`navigator.geolocation.getCurrentPosition`, enableHighAccuracy — stores `precisaoGps`/`origem:'gps'`) since they're standing at the plant; the point's talhão is auto-found via `pontoNoPoligono`/`talhaoDoPonto` and the **lat/lng is locked** so they can return to the exact spot. (The old "tocar no mapa" click-to-drop mode was removed — GPS only.) Each pin (a "ponto") carries a **código da plaqueta**, description, talhão/fazenda. Clicking a pin opens a panel with the point's **avaliações** over time — each visit has a date, observation and **photos**; a **📸 antes/depois comparador** puts any two of the point's photos side-by-side (defaults oldest vs newest, tap a thumbnail to advance the "depois") so treatment differences at the *same locked spot* are visible across visits. Photos in a **single avaliação** can also be tagged **antes/depois** (`papel` field on the foto doc) at posting time to store an inline side-by-side pair. Tapping any photo opens a **lightbox** that navigates prev/next through all the point's photos (◀ ▶, keyboard arrows, swipe). A **🧭 Abrir no Google Maps** button opens driving directions to the point (`maps/dir/?api=1&destination=lat,lng`). Photos are **compressed client-side** (`comprimirImagem` → canvas resize to ~1024px, JPEG q0.6) and stored as **base64 dataURI in Firestore** — one photo per doc so no doc bloats — since there's no Storage rules setup; `podeRegistrar()` adds points/avaliações, `podeGerenciar()` deletes (cascade). Collections: `avaliacaoPlantas` (`{codigoPlaqueta,descricao,talhaoId,talhaoNome,fazenda,lat,lng,...}`), `avaliacaoRegistros` (`{plantaId,data,observacao,...}`), `avaliacaoFotos` (`{plantaId,registroId,data,dataURI,...}`)

## `amostragem.html`

**soil/leaf sampling** — the field-collection companion to `analises.html` (which is the lab-results side). Leaflet map reusing registered talhão polygons; the admin generates a **fixed grid of collection points** inside a talhão (`gerarGrade` = zigzag/boustrophedon grid of ~N points via `pontoNoPoligono` filtering; N suggested from `areaHaPoligono`, admin-editable) with a **recuo mínimo da borda** (min setback in metres via point-to-edge distance, default 15 m — keeps points off the talhão margin to avoid bordadura masking; too-large recuo → 0 points). Regeneration on a talhão that already has points requires a **substituir** checkbox (deletes its pontos + coletas first). Admin edits points by **drag**, by **✥ Mover** (arms a one-shot map-click reposition — better on mobile than dragging), by **✏️ renomear**, by **🎯 Marcar ponto** (adds at current GPS, auto-assigned to the talhão via `talhaoDoPonto`), or delete. Points are **fixed year over year** so sampling repeats in the same spot. Solo and folha share the **same points** (tipo chosen at collection time). Field work is organized by **campanha = ano + rodada** — the year has multiple sampling rounds (default 3, admin-configurable count + optional labels in the `amostragemConfig/geral` doc `{rodadas,rotulos}`); sidebar has a ‹ year › selector plus **rodada chips** (1ª/2ª/3ª…). Each point is colored by the active (ano,rodada) status: pendente→grey / parcial→amber / completo (solo+folha)→green (coletas without a `rodada` field count as rodada 1). A field worker taps a point → **🎯 Confirmar coleta (GPS)** → `getCurrentPosition` computes **Haversine distance to the fixed point**; within **`MARGEM_M`=10 m** shows a green OK, beyond it a red warning (still registrable, flagged `dentroMargem:false`). Coleta modal captures tipo(s) solo/folha, data, obs → one `amostragemColetas` doc. `podeGerenciar()` (admin) creates/adjusts/deletes points; `podeRegistrar()` registers coletas. Collections: `amostragemPontos` (`{talhaoId,talhaoNome,fazenda,lat,lng,ordem,nome,...}`), `amostragemColetas` (`{pontoId,talhaoId,fazenda,ano,rodada,data,tipos:['solo','folha'],lat,lng,precisaoGps,distanciaM,dentroMargem,obs,coletadoPor,...}`), `amostragemConfig/geral` (`{rodadas,rotulos}`). Gated by `nivelAcesso('amostragem')`

## `clima.html`

**weather station viewer**, read-only — station `<select>` listing every doc in `clima/` (remembers the choice in localStorage; optional `fazenda` field on the station doc is filtered via `fazendasModulo.clima`), ‹ date › navigation in the station's `fuso`, live `status/ultimo` badge, "Agora" card (last minute of today), day `resumo` (ETo/chuva/T/UR/vento/rajada/Rs/insolação, completo-or-partial badge), Chart.js per-minute chart with chips (temperatura/UR/vento/radiação/chuva) decoded from `dias/{dia}.pontos` CSV via `campos`, a 🎯 **janela de pulverização** card (computed client-side per minute, no collector change: `avaliarPulv` = Delta T via Stull wet-bulb `bulboUmido` within `JANELA.dtMin–dtMax` 2–8 °C AND vento médio ≤ the limit of the selected application type (`MODOS_PULV`: 🚁 drone ≤ 5 km/h, 🚜 trator ≤ 7 km/h — toggle in the card, `modoPulv` remembered in localStorage via `window.setModoPulv`) AND no rain (`ctx`/`c1h`=0); "agora" verdict with reasons, a day timeline bar from `trechosPulv`, continuous windows ≥ 15 min, hours apto; plus a `🎯 Delta T` chart chip with the 2–8 band drawn by the `faixaDeltaT` plugin), a 💧 **lâmina sugerida** block inside the day resumo (`renderLamina` into `#laminaBox`: bruta = max(0, Kc × ETo(dia anterior) − chuva(dia anterior)) ÷ eficiência, shown in mm and m³/ha; fase/Kc from `FASES_KC` (nova 0,8 / formação 0,9 / adulta 1,0 / com cobertura 1,1) and sistema from `SISTEMAS_IRR` (gotejo 90% / aspersão 75%), both remembered in localStorage via `window.setFaseKc`/`window.setSistIrr`; previous day looked up in `resumos`/`resumosAno`; no soil-water balance, only yesterday), a 🌧️ **chuva acumulada** card (dia / mês / ano KPIs + bars per day of the month or per month of the year, from a per-year `resumos` query `where('data','>=',ano-01-01)`; also shows the station's own `rain_month` accumulator `chuvaMesMm` as a cross-check), a 📈 **histórico vários dias** card (`histVarHtml`/`renderHistVar`, chart `_chartHistVar`) plotting a chosen metric over a chosen range from the daily `resumos` — metric chips 🌡️ Temperatura (Tmax/Tmed/Tmin), 💧 Umidade (URmax/URmin), 💨 Vento (u2med·3.6/rajadaMaxKmh), ☀️ Radiação (RsMJ bars); range chips 7/15/30 days (within the 31-day `resumos` window); both remembered in localStorage via `window.setHistMetric`/`window.setHistDias`, and a history block from the lightweight `resumos` collection (last 31 days: ETo × chuva bars, table with ΔT mín–máx and 🎯 horas aptas for the selected drone/trator mode, 7/30-day balance chuva−ETo counting only `completo` days). **The spray-window criteria are duplicated**: `clima.html` (`JANELA`/`MODOS_PULV`, per-minute live view) and `clima/coletor.py` (`PULV_DT_MIN/MAX`, `PULV_VENTO_MAX_KMH` → `resumo.DTmin/DTmax/DTmed/horasAptoDrone/horasAptoTrator`) — change both together. Open by default like `agenda` (redirects only when `modulos.clima==='nenhum'`); menu item has no `acesso` key

## `gestao.html`

Its **Geral tab** (executive overview, `renderGeral`) has, beyond the KPI grid + ⚡ ações pendentes: 🎯 **progresso da safra** (adubação/pulverização bars: confirmed × previsto-até-hoje ▲, `_progressoSafra` scoped to `_safraJanela()` from `configAdubacao`), 🕒 **últimas atividades** (`_feedAtividades` — unified chronological feed of pulv/adub confirmed + drench realizado + estoque movs, `_tempoRelativo` labels), 📦 **estoque em alerta** (`_estoqueCritico` — negative saldo + projected-to-run-out-in-<30d from period consumption), 📈 **tendências** (`_deltaBadge`/`_metricasJanela`/`_janelaAnterior` — ha-pulverizado & gastos vs the equal-length previous window, ▲/▼% with red=more-spend), 🌧️ **chuva recente** (`_chuvaResumo` — mm/7d & 30d per fazenda from the now-loaded `pluviometria` collection, averaged across pluviômetros), and 🗺️ **mapa de atenção** (`_statusTalhoes`/`_desenharGeralMapa`/`_geralMap` — all talhões colored red=atrasado/yellow=pendente/green=em-dia/grey=sem-dados, click → `#geralStatusDetalhe` lists pendências). Its **Nutrientes tab** has 3 sub-views (state `nutrView`: `painel`/`mapa`/`tabela`): `painel` = Chart.js bar charts (total per nutrient + kg/ha ranking per talhão), `mapa` = a Leaflet map coloring talhão polygons by kg/ha of the selected nutrient (click a talhão → per-nutrient detail), `tabela` = the original table. `_calcNutrientes()` returns, per nutrient, the applied total (`total`/`porTalhao`) **and** the planned amounts (`plan`/`porTalhaoPlan` = `{ateHoje,total}`), computing each aplicação's planned date from `mesAno`+`semana` (`_dataPlanejadaAp`). `_nutriBarrasHtml()` renders per-nutrient comparison bars — **applied vs planned-até-hoje (▲) vs safra total (▮)** with an em-dia/atrasado badge — used both in the painel (kg total) and in the map's talhão detail (kg/ha). Its **Pulverizações tab** has 2 sub-views (state `pulvView`: `resumo`/`mapa`): `resumo` = the original dashboard (KPIs, por-praga, por-mês, rankings, histórico table), `mapa` = a Leaflet map coloring talhão polygons (blue scale) by **number of applications** in the period — click a talhão → a detail box (`#pulvTalhaoDetalhe`) lists **which** pulverizações and **when** (`_pulvAgrupaPorTalhao` expands each doc's `aplicacoes[]` — or the legacy `produtosUsados`/`dataRealizada` shape — into dated events; `_pulvMostrarTalhao` renders them most-recent-first). Its **Adubação tab** likewise has `resumo`/`mapa` sub-views (state `adubView`): the map colors talhão polygons (green scale) by **number of confirmed adubações** (`ap.feito`) in the period — click → a detail box (`#adubTalhaoDetalhe`) lists which adubações and when (`_adubAgrupaPorTalhao` uses `ap.dataFeito` with fallback to the planned date via `_dataPlanejadaAp`, filtered by `periodoFiltro()`; `_adubMostrarTalhao` renders modo/fase/mesAno + produtos most-recent-first). Leaflet 1.9.4 + Chart.js 4.4.0 are loaded in `gestao.html`'s head for this; the map/chart instances (`_nutriMap`, `_nutriCharts`, `_pulvMap`, `_adubMap`) are destroyed/recreated on every render since `tabContent` is wiped by `innerHTML`.
